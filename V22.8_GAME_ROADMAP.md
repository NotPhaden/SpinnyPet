# SpinnyPet — Game Ideas Roadmap

## Current games
- Coinflip
- Color Dice
- Cases
- Case Battle

## New game concepts worth adding

### 1. Pet Mines
A 5x5 board with hidden traps and pet/gem tiles. The player reveals tiles and can cash out at any point. The visual theme should use PS99-style gems/pets instead of generic casino art.

**Good fit because:** it is easy to understand, visually strong, and has clear progression.

### 2. Pet Plinko
Drop a glowing pet orb through a pin board. The orb lands in multiplier slots such as 0.2x, 0.5x, 1x, 2x, 5x and a rare jackpot slot.

**Good fit because:** the animation can be spectacular and it works naturally with diamonds.

### 3. Pet Crash
A pet rocket launches and the multiplier rises. The player cashes out before the crash. The crash point must be generated server-side and the client should only animate the already-authoritative result.

### 4. High / Low
Show one card and let the player predict whether the next card is higher or lower. Add streak animations and a cash-out option after every correct prediction.

### 5. Rock Paper Scissors — PvP
Players create a match, choose Rock/Paper/Scissors privately, and the server reveals both choices simultaneously. This would fit the existing lobby architecture used by Coinflip and Color Dice.

### 6. Pet Wheel
A large animated wheel with configurable diamond multipliers. Add rare jackpot segments and a server-side result so the animation only reveals the authoritative outcome.

### 7. Pet Duel
Two players select one pet from their inventory. The server compares a deterministic stat/value roll and the winner receives the agreed stake. This would make pets matter beyond selling/opening cases.

### 8. Mystery Pick
Nine animated cases/tiles appear. One contains the jackpot, several contain smaller multipliers, and some are blanks. The player chooses one and can optionally stop after revealing intermediate rewards.

## Recommended architecture
All games involving diamonds or inventory should use a dedicated Supabase RPC for the complete transaction:
1. validate session and balance/inventory;
2. reserve/deduct the stake;
3. generate the authoritative result server-side;
4. settle the payout atomically;
5. write history/activity;
6. return the result needed by the frontend animation.

The frontend should never decide the winning result.
